Data Abstraction

Understand how DBMS hides complex storage details and provides different levels of information to users.

TOPIC 1

What is Data Abstraction?

Data abstraction means hiding implementation details from users and applications while showing only the information that is relevant to them.

A DBMS can store data using complex storage structures, indexing methods, files and blocks. Users normally do not need to know these internal details.

Instead, users interact with the information they actually need.

Example

A student can view their attendance percentage without knowing where the attendance records are physically stored on the disk.

Key Points
  • Hides implementation details.
  • Shows only relevant information.
  • Improves security.
  • Improves flexibility.
  • Improves maintainability.
TOPIC 2

Physical Level

The physical level is the lowest level of data abstraction.

It describes how data is actually stored in the storage system.

It includes details such as:

  • File structures
  • Indexing methods
  • Data blocks
  • Storage details

Normal users do not need to see these low-level storage details.

Example

Attendance records may be stored in blocks on SSD storage and indexes may be used to locate records quickly.

Key Points
  • Lowest abstraction level.
  • Describes physical storage.
  • Includes file structures.
  • Includes data blocks.
  • Users normally do not see it.
TOPIC 3

Logical Level

The logical level describes the overall structure of the database.

At this level we work with:

  • Tables
  • Columns
  • Data types
  • Relationships
  • Constraints

Developers and database designers commonly work with this level when designing databases and writing queries.

Example

A Students table may contain Roll No, Name and relationships with a Courses table.

Key Points
  • Describes the overall database structure.
  • Uses tables and relationships.
  • Includes columns and data types.
  • Developers commonly work at this level.
TOPIC 4

View Level

The view level is the highest level of data abstraction.

It presents customized subsets of database information to different users.

Different users may therefore see different information from the same database.

Example

A hostel warden may see:

  • Roll Number
  • Name
  • Hostel Fee Status

The examination branch may instead see Roll Number, Name and Semester Marks.

Key Points
  • Highest abstraction level.
  • Provides customized views.
  • Different users can see different information.

Three Levels of Data Abstraction

Level What it describes Example
Physical How data is physically stored Blocks, files, indexes
Logical Database structure Tables, columns, relationships
View User-specific information Student/warden/exam views
TOPIC 5

Logical Data Independence

Logical data independence means that changes to the logical schema should not require application programs to be rewritten.

In simple words:

Logical schema changes
↓
Applications continue to work

This reduces application maintenance when the logical database structure changes.

Example

Suppose an Address field is changed into three separate fields:

  • Street
  • City
  • Pin Code

Applications that depend on the database can remain insulated from this logical change.

Key Points
  • Concerned with logical schema changes.
  • Applications are insulated from some schema changes.
  • Reduces maintenance work.
TOPIC 6

Physical Data Independence

Physical data independence means that physical storage changes can be made without affecting the logical schema.

The way data is physically stored can therefore change independently from the logical database structure.

Example

Attendance data can be moved from HDD storage to faster SSD storage. A new index can also be added without changing the SQL queries used by faculty members.

Key Points
  • Concerned with physical storage.
  • Logical schema remains unchanged.
  • Storage implementation can change independently.
TOPIC 7

Physical → Logical → View

The data abstraction hierarchy moves from the lowest physical level to the highest view level.

PHYSICAL Storage details
↓
LOGICAL Tables and relationships
↓
VIEW User-specific information
Example

The database server manages physical storage. Developers manage the logical database structure. A mobile portal displays a user-specific view.

Key Points
  • Physical is the lowest level.
  • Logical is the middle level.
  • View is the highest level.
  • Higher levels should be insulated from lower-level changes.

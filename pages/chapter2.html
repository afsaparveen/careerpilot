TOPIC 1

What is DBMS Architecture?

DBMS architecture describes where the different software components of a database system are located and how these components communicate with each other.

It helps in designing a database system according to requirements such as performance, security and scalability.

A database system can contain components such as a client, application server and database server.

Example

A student application sends a request to an application server. The application server communicates with the database server to retrieve the student's information.

Key Points
  • Describes the organization of DBMS components.
  • Describes communication between components.
  • Architecture affects performance.
  • Architecture affects security.
  • Architecture affects scalability.
TOPIC 2

One-Tier Architecture

In a one-tier architecture, the user interface and database engine run on the same machine.

There is no separate application server between the user and database.

It is simple to set up and is suitable for a single-user environment.

User Interface
↕
Database Engine
Same Machine
Example

A Python application using SQLite runs on one computer. Both the application and database are on the same machine.

Key Points
  • UI and database run on the same machine.
  • Simple architecture.
  • Suitable for a single-user environment.
  • No separate application server.
TOPIC 3

Two-Tier Architecture

In a two-tier architecture, a client application communicates directly with a dedicated database server.

The client contains the user interface and application-side functionality, while the database server manages the stored data.

Technologies such as ODBC and JDBC can be used to manage database connections.

Client
→
Database Server
Example

A Java desktop application directly connects to a MySQL database server to store and retrieve student records.

Key Points
  • Client directly communicates with database server.
  • Multiple users can connect.
  • JDBC or ODBC can manage database connections.
  • Database is directly exposed to clients.
TOPIC 4

Three-Tier Architecture

In a three-tier architecture, the client does not communicate directly with the database.

Instead, an application server is placed between the client and database server.

The three layers are:

  1. Presentation Layer — user interface.
  2. Application Layer — business logic and security.
  3. Database Layer — stores and manages data.
Client
→
Application Server
→
Database Server
Example

A mobile application sends a request to a Node.js application server. The server performs authentication and business logic before accessing the PostgreSQL database.

Key Points
  • Client does not directly access the database.
  • Application server is between client and database.
  • Business logic can be centralized.
  • Security can be centralized.
  • Database remains shielded.
  • Clients can remain lightweight.

TOPIC 5

Distributed Databases

A distributed database stores segments of data on two or more geographically separated servers.

Although data is stored across multiple servers, the system can present the data as one logical database.

Distributed databases are useful when an organization has systems operating from different locations.

Example

An educational organization has campuses in different cities. Each campus can maintain local attendance data while the complete system operates as one logical database.

Key Points
  • Data can be stored on multiple servers.
  • Servers may be geographically separated.
  • System can appear as one logical database.
  • Data may be synchronized between servers.
TOPIC 6

CAP Theorem

CAP theorem is important when discussing distributed systems.

CAP stands for:

C Consistency
A Availability
P Partition Tolerance

Consistency

Every node reflects identical data at a given moment.

Availability

Every request receives a timely response, although the returned data may not always be the most recent.

Partition Tolerance

The system continues operating even when communication between nodes is disrupted.

Examples

For financial applications, consistency is important because monetary data should not diverge.

For a digital notice-board website, availability may be important because showing an older notice can be preferable to making the website unavailable.

Key Points
  • C = Consistency.
  • A = Availability.
  • P = Partition Tolerance.
  • CAP is important in distributed systems.
  • There is a trade-off involving consistency and availability.
